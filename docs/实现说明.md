# 智道 iOS 演示实现

## 原生界面与原有算法

SwiftUI 管理生辰输入和播放状态；两块 SceneKit 视图使用真实 xyz 轨迹与透视相机。相同的旋转、俯仰和缩放同时作用于两图。每次生成生辰时，用两条种子轨迹的联合包围球确定一个共同中心与尺度，此后演化保持固定，不对两图分别归一化或逐帧自动缩放。曲线只连接原始相邻点，不按深度重排顶点。

计算由独立串行队列上的 JavaScriptCore 执行。捆绑全部模型与历法代码；无网页容器、网络脚本、CDN 或服务器。日历采用原系统的固定 UTC+08、公历输入、节气年月边界、23:00 换日和分钟口径起运。没有出生地、真太阳时或历史夏令时修正。

生成时仍用共同初值 `(0.1, 0, 0)`、600 模型单位暂态和 90 模型单位观察窗，分别计算生辰核与出生日期的流盘种子。页面打开即可查看演示；新输入重新排四柱并生成对应轨迹，不替换成预存示例。

## 连续演化

令 `X=(x,y,z)`，原扩展 Langford 向量场为 `F`，历法映射的目标八参数为 `p*(t)`，实际响应参数为 `q`：

```text
dX/ds = F(X; q)
dq/ds = (p*(t(s)) − q) / 1
ds/dt = 8/7 模型单位 / 公历日
```

沿用上游的固定 RK4 网格与采样网格，并在时辰、节气和个人起运/交运边界分段。没有在每次画面刷新时重新初始化动力状态。参数在边界因果地趋近新目标，不提前读取未来输入。

初始 9,001 点尾迹来自冻结出生时刻。它随后逐渐被连续段替换，滚动窗为 90 模型单位，对应 78.75 公历日。初始尾迹不能解释为出生之前的实际历史。生辰核的坐标数组始终独立保留。

目标每 40ms 推进 24,192,000 公历毫秒，即 `.32` 模型单位；观看速度为 7 天/秒。一次只允许一个计算包；性能不足时放慢观看，不能丢弃中间动力历史。暂停保留已显示帧，已算完但尚未显示的下一包缓冲到继续时使用。更换生辰与失效会话的晚到结果不得覆盖新状态。

## 范围

本演示的研究基础是人为定义的符号—参数—轨迹映射。参数响应额外增加八个内部动态状态；显示的是受时变输入驱动的三维轨迹，不直接等同于固定参数自治吸引子。静态形态校准不能证明连续模式处处混沌，也不能保证所有生辰均复杂或肉眼可区分。

本机只保存最近一次输入；没有登录、上传、广告、分析 SDK 或云端存储。关闭并重新打开应用会从该输入的出生时刻重新生成，不声称保存完整积分会话。

显示接口依据 Apple 的 [UIViewRepresentable](https://developer.apple.com/documentation/swiftui/uiviewrepresentable) 与 [SceneKit 原始线段几何](https://developer.apple.com/documentation/scenekit/scngeometryprimitivetype/line)。
