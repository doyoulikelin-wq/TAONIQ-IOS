# 智道 iOS 演示实现

## 原生界面与原有算法

SwiftUI 管理生辰输入和播放状态；两块 SceneKit 视图使用真实 xyz 轨迹与透视相机。相同的旋转、俯仰和缩放同时作用于两图。每次生成生辰时，用两条种子轨迹的联合包围球确定一个共同中心与尺度，此后演化保持固定，不对两图分别归一化或逐帧自动缩放。曲线只连接原始相邻点，不按深度重排顶点。v0.2.1 将右图的完整观察窗画为淡线，突出最后 160 个真实样点，并在实际积分末点显示亮点（包含慢速档的非采样网格末点）。亮点不另做动画，也不改变相机转速；切换速度时可直接观察它沿轨迹移动的快慢。

计算由独立串行队列上的 JavaScriptCore 执行。捆绑全部模型与历法代码；无网页容器、网络脚本、CDN 或服务器。日历采用原系统的固定 UTC+08、公历输入、节气年月边界、23:00 换日和分钟口径起运。没有出生地、真太阳时或历史夏令时修正。

生成时仍用共同初值 `(0.1, 0, 0)`、600 模型单位暂态和 90 模型单位观察窗，分别计算生辰核与出生日期的流盘种子。页面打开即可查看演示；新输入重新排四柱并生成对应轨迹，不替换成预存示例。

## 连续演化

令 `X=(x,y,z)`，原扩展 Langford 向量场为 `F`，历法映射的目标八参数为 `p*(t)`，实际响应参数为 `q`：

```text
dX/ds = F(X; q)
dq/ds = (p*(t(s)) − q) / 1
ds/dt = 8/7 模型单位 / 公历日
```

沿用上游的固定 RK4 网格与采样网格，并在时辰、节气和个人起运/交运边界分段。没有在每次画面刷新时重新初始化动力状态。参数在边界因果地趋近新目标，不提前读取未来输入。

初始 9,001 点尾迹来自冻结出生时刻或手动选定时刻。它随后逐渐被连续段替换，滚动窗为 90 模型单位，对应 78.75 公历日。初始尾迹不能解释为起点之前的实际历史。生辰核的坐标数组始终独立保留。

目标每 40ms 接收一个计算包，v0.2 按所选观看尺度决定其公历时长：大运十年／100秒、年／20秒、月／8秒、日／4秒、时辰／4秒。年和月使用固定 UTC+08 的公历加年／加月运算取得当前实际长度。每包至多两个模型单位；全部中间历法边界与 RK4 网格仍照常计算，不因切速度而改变 `ds/dt`。慢速「时」档可显示真实积分的非采样网格末点，不将这个临时末点写回固定积分网格。

一次只允许一个计算包；性能不足时放慢观看，不能丢弃中间动力历史。暂停保留已显示帧，已算完但尚未显示的下一包缓冲到继续时使用。切速度也保留在途包，下一包开始使用新节奏。更换生辰与失效会话的晚到结果不得覆盖新状态。

## 大运与年份定位

引擎返回 `dayunPeriods`：出生到首次起运为第 0 段「未起运」，后续时点从个人首次起运日期每次加十个公历年，干支由原历法 `dayunAt` 求得。只提供已开始的时段；最后一段的理论终点可以在当前时刻之后，但滑条不能进入未来。

大运滑条吸附到所选段的精确起点，年份滑条吸附到公历年初，出生年夹到实际出生时刻。年份选择不是把干支流年的边界改到元旦；干支年月仍由原模型的节气口径计算。

拖动先暂停并单独显示目标预览，松手才提交一次计算。定位期间保留已显示的轨迹，待新冻结种子完成后替换右图；左侧生辰核数组和共同视角继续保持。定位后再次播放从新种子末状态连续积分，不能把这个新会话解释为之前完整历史的恢复。每次定位更换请求标识和引擎会话，旧播放包或旧定位结果不得覆盖最后一次选择。

## 范围

本演示的研究基础是人为定义的符号—参数—轨迹映射。参数响应额外增加八个内部动态状态；显示的是受时变输入驱动的三维轨迹，不直接等同于固定参数自治吸引子。静态形态校准不能证明连续模式处处混沌，也不能保证所有生辰均复杂或肉眼可区分。

本机只保存最近一次输入；没有登录、上传、广告、分析 SDK 或云端存储。关闭并重新打开应用会从该输入的出生时刻重新生成，不声称保存完整积分会话。

显示接口依据 Apple 的 [UIViewRepresentable](https://developer.apple.com/documentation/swiftui/uiviewrepresentable) 与 [SceneKit 原始线段几何](https://developer.apple.com/documentation/scenekit/scngeometryprimitivetype/line)。
